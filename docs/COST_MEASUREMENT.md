## 1. Executive Summary

Phase 2 establishes a production-grade, auditable usage and cost instrumentation telemetry layer across the authoritative Node.js/Express backend. It measures the precise resource consumption of the existing evaluation pipeline without altering grading prompts, document payloads, evaluation sequences, model selections, or student report schemas.

Because live Gemini API calls are not executed during local offline development, all accounting mechanisms are validated through synthetic mock providers and regression tests. In accordance with strict engineering standards:
- **No live API keys were used or required.**
- **Zero fabricated token counts, latencies, or $0.00 figures are emitted.**
- **Missing provider metadata is explicitly surfaced as `null` and flagged as `UNKNOWN` or `UNAVAILABLE`.**
- **All regression tests (110/110 passed) run deterministically offline.**

### 2.2 Data Source Classification

Every recorded attempt, token metric, and cost calculation is strictly tagged with one of five authoritative data source types:

| Data Source | Description | When Applied |
| :--- | :--- | :--- |
| `ACTUAL_API` | Verified token counts extracted from real Gemini or Vertex AI response `usageMetadata` (`promptTokenCount`, `candidatesTokenCount`, `cachedContentTokenCount`). | Live Gemini API calls with valid metadata. |
| `ESTIMATED_COST` | Cost computed by multiplying verified or simulated token counts against the central versioned model pricing schedule. | Calculated cost fields. |
| `IMPORTED_BILLED` | Reconciled financial billing records exported from Google Cloud Billing (BigQuery export). | Reconciled operational audit reports. |
| `SIMULATED_MOCK` | Simulated token metrics generated by an offline test mock provider or benchmark harness. | Regression test suite and local simulations. |
| `UNKNOWN` | Missing, undefined, or empty usage metadata returned by the provider. Costs are set to `null` (never $0.00). | Provider failures, network errors, or omitted metadata. |

## 3. Versioned Pricing Engine (`server/pricing.ts`)

### 3.1 Active Pricing Version: `pricing_v2.1_2026_05`

Model pricing is isolated in `server/pricing.ts` using immutable versioned schedules. Rates are defined in USD per 1,000,000 tokens:

| Model Identifier | Prompt Input ($ / 1M) | Candidate Output ($ / 1M) | Cached Prompt ($ / 1M) | Cache Discount |
| :--- | :---: | :---: | :---: | :---: |
| `gemini-3.8-flash` | **$0.1000** | **$0.4000** | **$0.0250** | **75% Discount** |
| `gemini-flash-latest` | **$0.0750** | **$0.3000** | **$0.01875** | **75% Discount** |
| `gemini-3.1-flash-lite` | **$0.0375** | **$0.1500** | **$0.009375** | **75% Discount** |
| `gemini-4-argon` | **$0.2500** | **$1.0000** | **$0.0625** | **75% Discount** |
| `gemini-2.5-flash` | **$0.0750** | **$0.3000** | **$0.01875** | **75% Discount** |

### 3.2 Calculation Boundaries & Safeguards

1. **Cached Token Accounting:**
   $$\text{Uncached Input Tokens} = \max(0, \text{Total Prompt Tokens} - \text{Cached Content Tokens})$$
   $$\text{Prompt Cost} = \left(\frac{\text{Uncached Input Tokens}}{10^6} \times \text{Input Rate}\right) + \left(\frac{\text{Cached Tokens}}{10^6} \times \text{Cached Rate}\right)$$
2. **Currency Conversion:**
   $$\text{Total Cost INR} = \text{Total Cost USD} \times \text{Exchange Rate}$$
   The default exchange rate is configured via `process.env.USD_TO_INR_RATE || '85.0'` and can be overridden per request.
3. **Strict Zero-Fabrication Guarantee:**
   - If `inputTokens` or `outputTokens` is `null` or `undefined`, `isCostCalculable` is `false`, and `totalCostUsd` is `null` (`uncalculatedReason: 'MISSING_TOKEN_METADATA'`).
   - If the model is not registered in the active version schedule, `totalCostUsd` is `null` (`uncalculatedReason: 'UNKNOWN_MODEL'`).
   - If an invalid version string is requested, `totalCostUsd` is `null` (`uncalculatedReason: 'UNCONFIGURED_VERSION'`).
   - The engine **never** emits a default $0.00 cost for unknown models or missing metadata.

## 4. Immutable Usage Ledger (`server/usageLedger.ts`)

### 4.1 Per-Attempt Audit Trail

Each call to Gemini (including initial attempts, exponential backoff retries, and fallback transitions) generates an immutable `GeminiAttemptRecord`:

```typescript
export interface GeminiAttemptRecord {
  callId: string;
  jobId: string;
  correlationId: string;
  institutionId: string;
  pipelineStage: PipelineStage;
  requestedModel: string;
  actualModel: string;
  attemptNumber: number;
  isFallback: boolean;
  status: 'success' | 'failed' | 'timeout' | 'cancelled';
  errorCategory?: string;
  latencyMs: number;
  inputTokens: number | null;
  outputTokens: number | null;
  cachedInputTokens: number | null;
  totalTokens: number | null;
  usageSource: UsageSourceType;
  estimatedCostUsd: number | null;
  estimatedCostInr: number | null;
  pricingVersion: string;
  pricingTierUsed: string | null;
  timestamp: number;
}
```

### 4.2 Aggregated Evaluation Usage Summary

For each evaluation job, the ledger maintains an aggregate summary (`EvaluationUsageSummary`) that separates primary execution costs from retry/fallback overhead:

- **Token Consumption:** Net tokens consumed by successful calls, preventing double-counting of transiently failed attempts.
- **Retry & Fallback Cost Isolation:** `retryAndFallbackCostUsd` explicitly tracks wasted spend caused by 503s, 429s, or timeouts.
- **Usage Completeness:**
  - `COMPLETE`: All required model invocations produced complete token usage metadata.
  - `PARTIAL`: Some invocations produced metadata, while others did not.
  - `UNAVAILABLE`: Token metadata was absent across all invocations.
- **Atomic Disk Persistence:** Saved to `.data/evaluations/usage_ledger/<jobId>.json` using atomic temporary file write and rename patterns.

### 4.3 Multi-Tenant Access Control

- **Institution Isolation:** Instructors and institution administrators are strictly scoped to their own `institutionId`. Requests for usage summaries from other institutions return `null` / HTTP 403.
- **Operator Access:** Platform operators (`role: 'operator'`) possess universal audit access across all tenants.

### 4.4 Batch Statistics & Sample Size Discipline

The `getBatchStatistics()` API aggregates telemetry across evaluations. To prevent misleading statistical conclusions on small sample sizes:
- **Mean & Median:** Calculated for any positive sample size ($N \ge 1$).
- **P90 & P95 Percentiles:** Only calculated when $N \ge 10$. If $N < 10$, `sampleSizeSufficientForPercentiles` is flagged as `false`, and `p90CostUsd` and `p95CostUsd` are explicitly returned as `null`.

## 6. Runbook: Live Measurement via Vertex AI / Google AI Studio

When deploying to staging or production with active Google Cloud / Vertex AI credentials, follow this exact procedure to capture real-world baseline costs for Anatomy Guru without code changes:

### Step 1 — Configure Cloud Credentials
Set the environment variables in `.env` (or Google Cloud Run environment configuration):
```bash
GEMINI_API_KEY="your-production-gemini-api-key"
USD_TO_INR_RATE="85.0"
PRIMARY_MODEL="gemini-3.8-flash"
FALLBACK_MODELS="gemini-flash-latest,gemini-3.1-flash-lite"
```

### Step 2 — Run 10 Controlled Evaluations
Submit 10 representative 40–50 page handwritten student scripts via the UI or batch API using a designated institution account (`inst_anatomy_guru`).

### Step 3 — Query Batch Usage Statistics
Execute an authenticated request to `GET /api/usage/summary`:
```bash
curl -H "Authorization: Bearer <operator_or_instructor_token>" \
     "http://localhost:3000/api/usage/summary?institutionId=inst_anatomy_guru"
```

### Step 4 — Verify Output Metrics
Examine the returned report:
1. `dataSource` must be `'ACTUAL_API'`.
2. `sampleSize` must be $\ge 10$, confirming `sampleSizeSufficientForPercentiles: true`.
3. Compare `meanCostInr` and `p90CostInr` against the client's ₹9–₹14 baseline.
4. Verify that `retryAndFallbackCostUsd` is $< 5\%$ of total spend.
